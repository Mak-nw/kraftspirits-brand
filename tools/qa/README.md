# QA-набір site_brand

Спільний набір перевірок замість одноразових puppeteer-скриптів. Node ESM, єдина залежність — `puppeteer-core` (devDependency; Chrome береться системний:
`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, інший — `--chrome <шлях>` або `CHROME_PATH`).
Спершу запусти те, що вже є тут; одноразовий скрипт — лише коли набір не покриває задачу (і тоді користуйся `lib.mjs`).

- `--url` — за замовч. `http://localhost:5200/`; живий сайт: `https://mak-nw.github.io/kraftspirits-brand/` (база з `/` на кінці).
- `--widths 1200,1440,1920`, `--dpr 1,2`, `--scrollbar classic|none|both`, `--height 1080`.

- `--json` — результат JSON у stdout; `--out <dir>` — за замовч. `tools/qa/.out/` (у `.gitignore`; там чисті профілі Chrome, збірка `dist/` для S7/S9, `<інструмент>.json`).
- Код виходу: `0` — порушень немає, `1` — є, `2` — збій інструмента.

Службові параметри додаються автоматично: статичні заміри — `?age=ok&reveal=off&parallax=off`; анімаційні — `?age=ok&reveal=on&parallax=off`; перевірка воріт (D10) — без `age`.
Кожен запуск — новий Chrome з новим профілем (видаляється), усі процеси закриваються в `finally` (за PID, **без pkill**); dev-сервер перевірок запускай власний
(`npx vite --port 5340 --strictPort`, зупинка за PID). У dev-режимі overlay design-machine (`#__review-host`, `[id^="__"]`) ігнорується.

## check-ds: правила

Статичні (CSS/HTML/JS у `src/`, `partials/`, `*.html`; `tokens.css` — джерело, його не перевіряють): **S1** hex/rgb/hsl/іменований колір поза tokens.css (і в SVG-атрибутах HTML) ·
**S2** px/rem у font-size/line-height/letter-spacing/padding/margin/gap/width/height (+min/max) · **S3** `style="` у HTML, partials і JS-шаблонах · **S4** `text-decoration: underline`
поза футером і посиланнями в суцільному тексті (`.age-card__legal`, `.check-field`, `.contact-form__alert`, `.contact-success`; список — `underlineAllowSelectors` у `check-ds.allow.json`) · **S5** `var(--x)` на неіснуючий токен · **S6** невикористані токени (інформаційно) · **S7** дубль `id` в одному HTML (після `vite build` у `.out/dist`) ·
**S8** `@import`/`url()` у CSS на неіснуючі файли · **S9** `href`/`src` на неіснуючі файли у збірці, незаповнені `%плейсхолдери%`, шляхи зображень у `src/data/*.js` · **S10** кожен `.btn` у збірці має допустимий тон (`btn--gold|light|beige|green|teal|outline`; голий `.btn` без тону не має кольору) · **S11** (CLAUDE.md п. 5в) текст = лише ролі `.t-*`: у CSS поза `src/styles/base.css` (файл ролей) заборонені `font`, `font-size`, `font-family`, `font-weight`, `line-height`, `letter-spacing`, `text-transform`; у `tokens.css` — типографічні токени (`--font-size-*`, `--lh-*`, `--ls-*`, `--fw-*`, `--type-*`), на які не посилається жодна роль `base.css` (транзитивно): сторінкова/компонентна шкала = порушення. Автоматично дозволені: значення `inherit|unset|initial|revert` (наслідування, не стиль) і `font-variant-numeric` (вибір гліфів цифр, не начерк; лише рахується). Категорії у звіті: «сторінковий токен», «токен без ролі» (значення з токенів, але ролі немає — «значення з токенів» НЕ достатньо), «власне значення», «text-transform:none (скидання регістру ролі)», «em-частка» (`font-size: <em/%>` — оптична поправка гліфа; за замовчуванням порушення, виняток лише з рішенням замовника в `allow.json`), «токен поза ролями» (tokens.css). Конфіг: `check-ds.allow.json → static.s11` (`props`, `inheritValues`). @font-face пропускається.

Динамічні (за ширинами/смугою): **D1** роль `.t-*` → однакові font-family/size/line-height/weight/letter-spacing на всіх сторінках для того самого контексту (допуск 0.5px) ·
**D2** висоти `.btn .chip .nav-cell .select .product-card--catalog` однакові між сторінками · **D3** hscroll · **D4** консоль/4xx/failed · **D5** підкреслення (default/hover/focus-visible
через CDP `forcePseudoState`) поза футером/воротами · **D6** Tab-walker (на час проходу вимикає `scroll-behavior: smooth`, щоб кільце міряли після завершення прокрутки): кільце focus-visible ≥3:1 (спершу за ланцюжком фонів, при сумнівах — за пікселями скриншота) ·
**D7** рівно один h1, без пропусків рівнів; ворота 18+ (діалог поверх inert-сторінки) — рівно один видимий заголовок, на який посилається `aria-labelledby` діалогу · **D8** контраст ролей `.t-*` ≥4.5:1 (≥3:1 великий; disabled не рахується; сумнівні міряються піксельно) · **D9** alt/імена кнопок і полів ·
**D10** вікові ворота показуються без `?age=ok` · **D11** центрування контролів з підписом · **D13** (`tools/qa/typo-d13.mjs`; CLAUDE.md п. 5в) кожен текстовий вузол (елемент із прямим текстом + input/textarea/select; поза `design-system.html`, `--d13-ds` вмикає) має обчислений стиль (family, size, weight, line-height, letter-spacing, text-transform, font-style), що збігається з ≥1 роллю `.t-*`. Таблицю ролей збирає сама сторінка: для кожного `.t-*` із `base.css` створюється тимчасовий елемент (у батьках `text-transform: none` і `uppercase` — якщо регістр відрізняється, роль його успадковує й порівнюється з будь-яким) і береться computed на поточній ширині. Допуски: size 0.25px, line-height 0.5px, letter-spacing 0.15px (`allow.json → dynamic.d13`). Порушення: «текст поза ролями» (нуль збігів; у звіті найближча роль і чим відрізняється) і «роль .t-x перевизначена у CSS» (клас є, стиль ≠ ролі, напр. `.product-card .t-price {font-family}`). Інформація: збіг із роллю лише за значеннями, без класу `.t-*` (дві РЕКОМЕНДАЦІЇ, не fail: (1) строга — вузол має стиль ролі, `.t-*` немає, і стиль ≠ стилю батька, тобто це не наслідування; у звіті «без .t-*»; (2) роль лише успадкована від предка — «успадковано: …» за типами вузлів: product `dd`/`.strength`/`.product-volume`, таби коктейлів, підписи feedback тощо; повний список у `<out>/d13.json` → `noClass` / `implicit[].inherited`); «одна семантика — одна роль» (кластеризація за h1–h4 і BEM-суфіксом `__title/__desc/__text/__label/__num/__lead…`: якщо в одному кластері різні начерки — перелік сторінок). Ворота 18+ збираються окремо. Не бачить: `::before/::after content`, `::placeholder`, текст усередині `<svg>`/`<option>`. · **D12** (`tools/qa/grid-d12.mjs`; у загальному прогоні, крім design-system.html) сітка колонок: 10 колонок, контейнер = `--vw` − 2×поле, gap; єдина сітка сайту (рішення замовника 16.10.2026; токени `--grid-*` у `tokens.css`): поле 202.9u / gap 40u / колонка 115.42u, 1514.2u — одна для ВСІХ сторінок, header і footer (профіль `catalog` у `check-ds.allow.json → grid`; окремого профілю 50u/5u (старі) для товару/контактів/фідбека більше немає). Для кожного блока (секції, колонки/ітеми flex/grid, заголовки, зображення, картки, футер-колонки, текстові блоки з власним положенням) лівий край має лежати на ПОЧАТКУ колонки, правий — на КІНЦІ (допуск: ≤0.5px норма, 0.5–1px «підозріле» (лише в `grid-d12.json`), >1px порушення; ширина = n·колонка + (n−1)·gap подається як «колонок факт/очікув.»). Край на краю в'юпорта (full-bleed) не перевіряється, а його вміст — так; внутрішній край блока-половинки може лежати на осі в'юпорта або середині gap. Край, що збігається з уже перевіреним краєм блока-предка, не дублюється; текст, стиснутий за вмістом, перевіряється лише по краю, притиснутому до поля предка. Картка/панель із власним фоном чи рамкою не на всю ширину = завершений компонент (внутрішність не перевіряється; `--grid-deep` вмикає). Не перевіряються: кнопки/чіпи/селекти/поля/посилання навігації (розмір за вмістом), декоративні абсолютні шари й `aria-hidden`, елементи <60u×20u, комірки списків (dt/dd/li). Звіт показує, чи блок збігається з сіткою іншого профілю. Що D12 НЕ бачить — `reports/grid-audit.md`, розділ «Сліпі зони». Метод — по РЕАЛЬНОМУ тексту, не арифметикою line-height: перший символ підпису беремо через `Range.getClientRects()` (content-area шрифту; `top` = базова лінія − округлений ascent, Chrome округлює ascent/descent), метрики шрифту — з canvas (`fontBoundingBoxAscent/Descent`, `actualBoundingBoxAscent` літери «H» = cap-height) → базова лінія й ОПТИЧНИЙ центр = центр великих літер `baseline − cap/2`. Чекбокс/радіо: центр боксу = цей оптичний центр першого рядка (допуск 0.5px, `alignCheckTolerancePx`; 1–3 рядки, перевіряється лише перший). Іконка у `.btn__inner`/`.nav-cell`: центр іконки = центр content-area тексту (допуск 1px, `alignIconTolerancePx`) + діагностично відхилення від cap-центру (інформація). Що D11 НЕ бачить: розтушовування й округлення на растері — для цього `qa:ink`.

**Піксельний ink-замір (`npm run qa:ink`, `tools/qa/ink.mjs`).** Знімок в'юпорта при dpr 4 «з» і «без» елемента (бокс `visibility:hidden`, перший гліф `color:transparent`); різниця = маска чорнила без впливу фону; центр = середина рядків маски (поріг 50% піку). Малу першу літеру міряємо як велику (cap-height). Це еталон для підозрілих місць; допуск 0.5px. Обмеження: `setViewport({deviceScaleFactor})` — емуляція, у ній Chrome прив'язує базову лінію тексту й межі боксів до ЦІЛИХ CSS px (у справжньому hi-dpi — до px пристрою, там похибка ≤0.25), тому ink-похибка залишкового округлення зсуву ≤0.5px; зсув боксу на 1px піксельний замір ловить не на всіх ширинах (на 1200 — ні), 2px — завжди; layout-D11 ловить 1px на всіх.

Звіт: `правило  файл:рядок / селектор / сторінка@ширина  = значення — повідомлення`. Однакові повідомлення групуються.

### D14 — контраст тексту на зображенні, по літерах (`tools/qa/text-on-image.mjs`)
D8 міряє один коефіцієнт на весь бокс ролі й не бачить змішаного фону (небо + лози) — дефекти hero бочок і «Ціни» екскурсій проходили з 0. D14 міряє **піксельно по літерах**. Для кожного видимого текстового вузла (елемент із прямим текстом), під яким у стеку `elementsFromPoint` є `img/video/canvas`, `background-image` (url або градієнт) чи `::before/::after` з фоном-картинкою:
1. прокрутка тайлами по висоті в'юпорта; у кожному тайлі 3 знімки при незмінній розкладці (вимикаються transition/animation і dev-overlay): (а) `-webkit-text-fill-color: transparent` = **пікселі під літерами**; (б) заливка тексту чорна; (в) біла. Покриття літери = (в − б)/255 — маска чорнила, незалежна від кольору й фону. `color` НЕ чіпаємо (фони/рамки/іконки від `currentColor` лишаються);
2. на кожну літеру (`Range` на символ) беруться пікселі з покриттям ≥0.6 (запас 0.3), ефективний колір чорнила = computed `color` × alpha × opacity предків, накладений на піксель фону; контраст WCAG чорнило ↔ піксель;
3. частка пікселів літери нижче порога: **4.5** звичайний, **3** великий (≥24px або ≥18.66px bold; пороги = `dynamic.textMinContrast/largeTextMinContrast`). Літера «погана», якщо >50% її пікселів нижче порога; **вузол FAIL, якщо погана хоч одна літера**. Літери, перекриті іншим елементом (fixed-хедер, оверлей), не рахуються.
Звіт: `мін. контраст`, скільки літер погані, які саме (`погані: «rn»`), що під текстом (`img` / `background-image` / `градієнт`), `y`. Дані → `<out>/d14.json`. Параметри: `--d14-all` (усі сторінки, не лише профіль), `dynamic.d14Pages` у allow.json. **Винятків у `allow.json` для D14 не додавати**: FAIL = знахідка для виконавця (контраст виправляється розкладкою/кадром фото, не винятком).
Не міряється (лише лічильник в info): текст над `<canvas>` (WebGL-карта maplibre — кадр між знімками нестабільний; атрибуція карти — перевіряти візуально); градієнтна заливка тексту; тіні тексту не враховуються (`text-shadow` у знімках вимкнено).
**Профіль `parallax=on`** (`D14_PARALLAX` у `text-on-image.mjs`; зараз `barrels` → `#price`): основний прохід іде з `parallax=off`, тому не бачить випадку, коли `data-parallax` перезаписує кадр фото (`scale`/`transform-origin` належать паралаксу). Додатковий прохід відкриває сторінку з живим паралаксом і міряє секцію в 3 позиціях прокрутки (секція входить / мітка біля верху вікна / секція виходить; перед заміром чекає згасання інерції). Позитивний контроль: той самий прохід із `--lp-offers-bg-scale:1` (кадр без наближення, як було до виправлення) МАЄ дати порушення (мітка «Кентуккі (США)» ≈ 1.0–1.5:1), інакше D14 повідомляє «контроль не спрацював».
**Позитивні контролі** (у КОПІЇ проєкту): (а) ширина H1 hero бочок = 10 колонок (`--size-heading-w` → `--grid-span-10`: H1 в один рядок на лозах) → D14 FAIL на barrels `h1.hero__title` на всіх 4 ширинах × classic/none (раніше контроль — токен `--size-lp-hero-title-w` = 12 колонок, літери «rn», мін. 1.07:1; тепер H1 завжди `.heading-center` — 4 колонки); (б) `.hero--lp { color: #fff }` (білий текст на небо/лози) → FAIL h1 і підзаголовка hero на barrels/excursions (мін. 1.45–1.95:1) на всіх ширинах; на чистому стані ці вузли проходять.

### D12 — стабільність під навантаженням (`waitLayoutStable` / `collectStable` у `lib.mjs`)
Флейк: під навантаженням (≥3 паралельних Chrome) barrels@1728 / index@1440 інколи давали зсув УСІХ блоків на 7.5px (= половина смуги 15px, classic) і «порушення» D12, які наступний прогін не відтворював.
Причина — гонка смуги прокрутки: `--vw` виставляє `src/js/viewport.js` асинхронно (ResizeObserver за шириною html), а смуга з'являється/зникає, коли довантажуються шрифти/зображення й змінюється висота; замір у вікні «clientWidth уже змінився, `--vw` ще старий» зсуває сітку.
Лікування (у самому інструменті, сайт не чіпаємо; `scrollbar-gutter` у тесті НЕ вмикаємо — це сховало б реальну поведінку classic-смуги):
1. `waitLayoutStable(page)` — чекає ПІДРЯД 4 кадри rAF без змін: `clientWidth`, ширина смуги (`innerWidth−clientWidth`), ширина html, `scrollHeight`, відбиток геометрії ≤80 елементів (0.01px) І `--vw` = round(ширина html) (viewport.js догнав); ліміт 8 с;
2. `collectStable(page, collect, cfg, sig)` — збір повторюється до збігу ДВОХ замірів підряд (підпис = clientW, `--vw`, краї усіх блоків); максимум 3 заміри → голосування 2 з 3; якщо жодні два не збіглися — береться замір із clientW = `--vw` і в звіт іде `note` «нестабільний макет» (рахується в `stats.grid.unstable`); `stats.grid.revoted` = скільки сторінко-ширин потребували 3-го заміру.
Те саме застосовано до D18. Перевірка стабільності (16.10.2026): 5 прогонів поспіль `--rules D12 --pages barrels --widths 1728 --scrollbar classic` і `--pages index --widths 1440 --scrollbar classic` при 3 паралельних циклах check-ds (≥4 браузерів, load average ≈35) → підпис геометрії всіх блоків і лічильники однакові в усіх 5+5 прогонах (barrels 48 блоків, index 44). Старий код у тих самих умовах також дав 5/5 однакових — флейк рідкісний і природно не відтворився; механізм відтворено синтетично (смуга зникає на 250мс після готовності сторінки, замір через 0–120мс): одноразовий замір = 10/10 розбіжностей (у т.ч. стан clientW 1728 / `--vw` 1713 = зсув 7.5px), `collectStable` = 0/10.

### Винятки — `check-ds.allow.json`
Запис `{ rule, file?, selector?, page?, prop?, value?(RegExp), reason, date, decision }`; без `reason` ігнорується. **`selector` — ТОЧНИЙ збіг класів/тегів** (не підрядок): кожен токен виняткового селектора (розбиття за не-`[A-Za-z0-9_-]`) має бути серед токенів селектора порушення, тож `site-header__logo` НЕ маскує `site-header__logos`; потрібен інший клас — окремий запис. `file`/`page` — як і раніше підрядок. Коментарі CSS/HTML ігноруються автоматично. Нові винятки лише з рішенням замовника.
Секції `dynamic` і `static` — пороги й дозволені контексти (підкреслення: `.site-footer`, `.age-card__legal`).

## states
Для сімейств `btn` (gold, light, beige, green, teal, outline), `nav-cell` (outline, fill, ghost), `arrow-btn`, `chip`/`chip-picker` (+selected), `nav-link` (+on-light) знаходить реальний елемент на сторінках,
проходить default → hover (safeHover) → focus (клавіатурний) → active (mouse down, відпускання поза елементом) → disabled (тимчасовий `aria-disabled`) і порівнює computed bg/text/border/icon-filter
з розв'язаними `--btn-<варіант>-<властивість>-<стан>` (ST1); транзиції: default/hover = `--btn-transition-duration` (≥0.3s), focus/active = `--btn-transition-duration-focus` (ST2); кільце за `--focus-ring-width` (ST3).
Не покрито: select, check, row-faq, row-product, catnav, thumb, volume, choice.

## arch
Піксельний замір скриншота: покриття кольору арки (`--color-green`) на тлі `--color-card-bg-catalog` уздовж ліній через центр арки; сума = товщина в device px. Критерії: мін. ≥0.5×очікуваної (2.476u×DPR), розкид сторони між картками ≤0.5 device px (верх — лише мінімум: у центрі арка товстіша).

## Як додати перевірку
1. Статичну — у `ds-static.mjs` (`want('Sx')` + `add({rule,file,line,selector,value,msg})`); динамічну — у `ds-dynamic.mjs` (дані збирай у `COLLECT`, аналізуй нижче, `addV`). Нова заборона замовника = нове правило S/D + рядок тут і у `CLAUDE.md`.
2. Окремий інструмент — файл `tools/qa/<name>.mjs` з `export async function runX(o)` → `Report`, + `runMain` під `import.meta.url`, скрипт `qa:<name>` у `package.json`, підключення в `run.mjs`.
3. Позитивний контроль обов'язковий: внеси навмисне порушення в КОПІЮ проєкту (не в проєкт) і переконайся, що перевірка падає.

## Відомі обмеження
- Dev-сервер Vite стежить за файлами репо, зокрема за `tools/qa/.out` (профілі Chrome) і за чужими правками коду: це перезавантажує сторінку під час заміру («Execution context was destroyed»). Збір D12/D18/D19 повторює замір після перезавантаження (`evalRetry`); для довгих прогонів задавай `--out` ПОЗА репо.
- Фони, намальовані картинками/псевдоелементами, ланцюжок фонів не бачить; для D6/D8 це компенсується піксельним заміром лише для «підозрілих» елементів.
- `hscroll`: у `html` стоїть `overflow-x: clip`, тому `scrollWidth` не показує зріз — додатково шукаються елементи за межами в'юпорта.
- Навігаційні `catalog.html#<категорія>` — не DOM-якорі (хеш читає `catalog.js`), links їх не вимагає.
- Живий сайт: без навантаження (послідовно, один Chrome на комбінацію).
