# site_brand — YasnoCraft × Bazylsprings

Vite (vanilla), багатосторінковий: кожен `*.html` у корені — окрема сторінка. Дизайн знято з Figma `JO2rsMY0AhFutzAQwfl0WV` (сторінка des_brand 194:1183).

## Запуск
```
npm install
npm run dev      # http://localhost:5200 (--strictPort: якщо порт зайнятий, команда падає, а не бере інший)
npm run build    # dist/, base /kraftspirits/ (або BASE_PATH, див. «Деплой»)
npm run preview  # http://localhost:5200
```
Живий опис дизайн-системи: `/design-system.html`.

## Деплой
- Репозиторій: https://github.com/Mak-nw/kraftspirits-brand (GitHub Pages, сайт: https://mak-nw.github.io/kraftspirits-brand/).
- Workflow `.github/workflows/pages.yml` (Deploy site to Pages): на push у `main` і вручну (`workflow_dispatch`) робить `npm ci`, `npm run build` з `BASE_PATH=/<назва репозиторію>/` і публікує `dist/`.
- Змінна `BASE_PATH` задає base збірки та `vite preview` (див. `vite.config.js`): без неї — `/kraftspirits/` (старий сайт), dev завжди `/`. Значення нормалізується до `/…/`.
- Локальна перевірка продакшн-збірки під новим репо: `BASE_PATH=/kraftspirits-brand/ npm run build && BASE_PATH=/kraftspirits-brand/ npx vite preview` (сайт за `http://localhost:4173/kraftspirits-brand/`). Для `vite preview` потрібен той самий `BASE_PATH`, що й для збірки.
- `dist/`, `node_modules/` та службові файли не комітяться (див. `.gitignore`).

## Структура
- `partials/` — `<!--@include name-->` (вкладені; параметри `<!--@include name title="..."-->` → `{{title}}`).
  Розширення: `{{key|типове}}` — значення за замовчуванням; `{{#key}}…{{/key}}` — блок лише якщо `key` задано; шлях `sections/hero`, `components/btn` підтримується. Значення параметрів не можуть містити `"`.
- `partials/components/` — повторювані блоки: `btn` (variant, href, text, опц. price — рендериться як `.t-price` перед текстом у `.btn__inner`, опц. arrow/arrow-class/text-class), `faq-item` (q, a, опц. open=" open" expanded="true"), `chip` (label), `stat` (num, label), `arrow-btn` (label, attr, mod).
- `src/styles/tokens.css` — ВСІ кольори, шрифти, розміри, відступи, радіуси, контейнери (коментар = Figma-вузол).
- `src/styles/base.css` — reset, типографічні ролі `.t-*`, теми `.theme-*`.
- `src/styles/components/*.css` — button, nav, product-card, accordion, arrow-button, chip.
- `src/styles/fonts.css` — локальні @font-face (EB Garamond, Manrope, Cormorant; кирилиця є).
- `src/js/` — скрипти сторінок. `public/assets/{img,fonts,icons}` — ассети з Figma.

## Масштаб і адаптив
`--u` = 1 px макета. Основний діапазон **1200–1920 — піксель у піксель** (`--u` = 1 на 1920, 0.625 на 1200; усі розміри `calc(N * var(--u))`). Адаптив (рішення замовника 2026-10-19; гілка `responsive`) додано ЛИШЕ в медіа-запитах поза цим діапазоном: **> 1920** (u росте до 2560, далі сцена 1920u по центру, фони full-bleed), **1024–1199** (u = vw/1920, підлоги px для малого тексту), **768–1023** (сітка 8 колонок, u = vw/1100), **< 768** (сітка 4 колонки, u = clamp(0.5, vw/640, 0.9)). Breakpoint-токени — в кінці `src/styles/tokens.css` (блок «АДАПТИВ»), розкладки — `src/styles/responsive/*.css` (імпорт у кінці `main.css`). Рішення, таблиці, файли, що потребує погодження — `docs/responsive.md`.

## Правило
Нові блоки будуються лише з токенів і компонентів. Новий компонент спершу додається в `design-system.html` (+ `src/styles/components/`), потім використовується на сторінках. Жодного хардкоду кольорів/px поза `tokens.css`, жодних inline-стилів, жодних посилань на figma.com.


## Сторінки-заглушки і 404
Не створені сторінки (`faq.html`, `offer.html` — справжні сторінки, див. «FAQ» і «Юридичні сторінки»; `cart.html`, `checkout.html`, `account.html` — створені, див. «WooCommerce-сторінки»; `about.html` — рукописна авторська сторінка (не шаблон lp): CSS `src/styles/pages/about-page.css`, ілюстрації `partials/about/`, JS `src/js/about.js`) — окремі HTML у корені: `head-icons` + `head-fonts`, header, `<main class="under-construction-page">` з `<!--@include sections/under-construction page="Назва"-->`, footer. Одна розмітка в `partials/sections/under-construction.html` (параметри `page`, `title`, `text`, `id` — якір секції; `offer.html` передає `id="rules"`, тому `offer.html#rules` з вікових воріт і форми зворотнього зв'язку веде на секцію: відступ під пілюлею дає `scroll-padding-top` на `html`, окремого `scroll-margin-top` не потрібно; CSS `src/styles/under-construction.css`; опис — у `design-system.html#under-construction`). `<title>` — «Сторінка в розробці — YasnoCraft × Bazylsprings». У `vite.config.js` нічого додавати не треба: кожен `*.html` у корені потрапляє в `rollupOptions.input` автоматично.
- **Нова заглушка:** скопіювати будь-яку з наявних (напр. `404.html`), змінити `page="…"`. Посилання на неї в header/footer уже відносні (`name.html`).
- **Коли з'явилась справжня сторінка:** замінити вміст файлу (залишити header/footer include), прибрати `under-construction`; секцію не видаляти — її використовує `404.html`.
- **`404.html`:** GitHub Pages віддає його для невідомих URL будь-якої глибини; має `<base href="%BASE_URL%">` (плагін `html-partials` у `vite.config.js` підставляє `config.base`: `/kraftspirits/` у build/preview і `/` у dev; сирий плейсхолдер не лишається ні в dev, ні в dist), тому відносні посилання header/footer/кнопок ведуть від кореня сайту. Заголовок «Упс.. Сторінка не знайдена». Якір «Контакти» (`#contacts`) на 404 веде на головну (через `<base>`).

## Токени кнопок (стани)
Єдина система в `src/styles/tokens.css`, блок «Кнопки: стани» (218 токенів `--btn-*` + 3 `--focus-ring-*`), живий опис і матриця станів — `design-system.html`, розділ «Стани кнопок».
- **Схема імені:** `--btn-<варіант>-<властивість>-<стан>`. Властивість: `bg` · `text` · `border` · `icon-filter` · `opacity`. Стан: `default` · `hover` · `focus` (:focus-visible) · `active` (:active) · `disabled` (:disabled, `aria-disabled="true"`); `selected` — лише для перемикачів (`aria-expanded`, `aria-pressed` / `.is-active`, `.is-open`, `:checked`). Варіанти: `gold` `light` `beige` `green` `teal` `outline` (`.btn--*`), `nav-outline` `nav-fill` `nav-ghost` (`.nav-cell--*`), `arrow` (`.arrow-btn`); **`.btn` обов'язково з тоном** (голий `.btn` більше не золотий і не має кольору; перевіряє check-ds S10; `btn--gold` — лише бочки, сертифікат 50 L); легші групи: `chip`, `chip-picker`, `volume`, `select`, `select-field`, `check`, `row-faq`, `row-product`, `catnav`, `navlink`, `thumb`.
- **Значення — лише посилання на наявні токени** (`--color-*`, `--color-hover-*`): нових кольорів немає, жодного видимого значення default/hover/focus не змінено; старі `--color-hover-*` лишаються джерелами значень.
- **Правила станів:** `focus` = `hover` (відрізняється тривалістю 0.15s і кільцем); `active` = hover, затемнений: `color-mix(in srgb, <bg-hover> var(--btn-active-mix), var(--color-black))` (`--btn-active-mix` = 92%) + для `.btn` `scale(var(--btn-active-scale))` 0.985, перехід `--btn-transition-duration-focus`; `disabled` = default + `--btn-disabled-opacity` (= `--opacity-disabled` 0.4, значення, що вже було в проєкті), `--btn-disabled-cursor: not-allowed`, без hover/focus/active-змін, стрілка не зсувається; нативний `:disabled` ще й `pointer-events: none`.
- **Прив'язка в компонентах:** варіант (`.btn--green`, `.nav-cell--outline`, `.arrow-btn`, `.chip`…) задає КОНТЕКСТНІ змінні `--btn-bg` / `--btn-text` / `--btn-border` (+ `-hover`, `-focus`, `-active`, `-disabled`, `-selected`), а база компонента (`.btn`, `.btn__inner`, `a.nav-cell--*:hover` …) читає лише їх. Спільні: `--btn-transition-duration` (= `--duration-fast`), `-duration-base`, `-duration-focus`, `--btn-transition-ease`, `--btn-icon-nudge-hover`, `--btn-icon-color` (іконка = `currentColor`).
- **Фокус-кільце:** глобальне `:focus-visible` (base.css) читає `--focus-ring-width / -offset / -color` (= 1px · 3u · currentColor); кнопки — ті самі значення як `--btn-focus-ring-width / -offset / -color-auto`; `--btn-focus-ring-color-on-dark` (beige: пілюля хедера, nav-cell) і `-on-light` (green: перемикач check).
- **Новий варіант кнопки:** (1) у tokens.css скопіювати групу `--btn-green-*` → `--btn-<новий>-*` (посилання на палітру; hover — `--color-hover-btn-<новий>` у блоці «Hover-стани»); (2) у `button.css` додати блок `.btn--<новий> { --btn-bg: … }` за зразком `.btn--green` (15 контекстних змінних); (3) додати рядок у матрицю design-system і перевірити контраст ≥ 4.5:1 для default/hover/active.
- **Плитка-радіо `.topic-tile`** (feedback.html): токени `--btn-choice-*` (блок «Зворотній зв'язок» у tokens.css) — лише посилання на `--btn-select-field-*` (default/hover/focus) і `--btn-green-*` (selected); нових кольорів немає. **Обводка вибраної плитки** (коментар 9b2cd34f): `aria-checked="true"` має ПОСТІЙНЕ кільце `outline` тим самим, що в кнопок на `:focus-visible` (1px · offset 3u · green on-light): токени `--btn-choice-ring-width-selected / -offset-selected / -color-selected` (аліаси на `--btn-focus-ring-*` і `--btn-choice-ring-color`); selected+focus-visible — кільце вдвічі товще (`--btn-choice-ring-width-selected-focus`); hover невибраної кільця не дає (лише зміна заливки). Disabled не передбачено.
- **Демо:** класи `.is-hover / .is-focus / .is-active` існують лише в `design-system.css` і читають ті самі контекстні змінні (значень не дублюють).

- **Плавний перехід фільтра/сортування** (`src/js/catalog-motion.js`, рішення замовника: «щоб не скакало в секунду»): вузли карток не перестворюються (кеш за slug у catalog.js), змінюються лише `hidden` і порядок у DOM. FLIP на окремих CSS-властивостях `translate`/`scale`/`opacity` (WAAPI, easing `--ease-out`): картки, що відпали, лишаються на своєму місці (`.is-leaving`, absolute) і гаснуть `--duration-fast` (0.45s, opacity → 0, scale 0.98); решта переїжджає на нові місця `--duration-base` (0.7s) зі стартом через `--catalog-leave-lead` (= 0.5 × fast) і легким stagger за порядком `--catalog-move-stagger` (= 0.4 × `--reveal-stagger`, не більше 8 кроків); нові з'являються opacity 0→1 + зсув `--reveal-shift`, затримка `--catalog-enter-delay` (= 0.3 × base) + stagger `--reveal-stagger` (0.12s, не більше 6 кроків). Розкладка (grid, висота, позиція футера) одразу кінцева — футер плавно їде на нове місце через `translate` (без анімації layout-властивостей, тож layout-shift лише в межах 500 мс після кліку, у метриці CLS не рахується); порожній стан («Нічого не знайдено») з'являється fade + зсув, а зникає клоном-«привидом» (fade). Швидкі повторні кліки: перед кожною зміною знімається поточний візуальний стан (rect + opacity), попередні анімації скасовуються, нові стартують з цього стану — без стрибка, без «привидів» і дублікатів. `prefers-reduced-motion`, `?reveal=off` і автоматизація (`navigator.webdriver` без `?reveal=on`, як у reveal.js) — миттєво, як раніше. ## Темп руху і акордеони

Мова руху — плавна, «дорога»: усі тривалості в `src/styles/tokens.css` (літералів у компонентах немає). `--duration-fast` 0.45s (колір/фон: кнопки, чіпи, nav, стрілки, пункти select, згасання старої картки), `--duration-base` 0.7s (масштаб, opacity, поява нової картки, cross-fade фото товару), `--duration-reveal` 1.1s + `--reveal-stagger` 0.12s, `--duration-bg` 1.4s, `--duration-liquid` 1.4s, `--duration-wave` 4s, `--ease-out` cubic-bezier(0.22, 0.61, 0.36, 1). Для клавіатури `--duration-focus` 0.15s (перехід при `:focus-visible` короткий). JS читає тривалості через `cssMs` (`src/js/duration.js`; мінімізатор у збірці дає `.45s`/`1.1s`, одиницю розбираємо явно) — таймери слайдера (`fast + base + запас`) і reveal (`reveal + stagger·i + запас`) лишаються синхронними з CSS. `prefers-reduced-motion: reduce` — усе миттєво.

Акордеони (`details.acc`: FAQ і сторінка товару) відкриваються/закриваються плавно: `src/js/accordion.js` перехоплює клік по `summary`, анімує висоту `details` та opacity тіла (Web Animations API, `--duration-accordion` 0.85s, `--ease-accordion`), при швидких повторних кліках розвертає анімацію з поточної висоти; `aria-expanded` оновлюється одразу, Enter/Space працюють, без JS — нативний `details`. Іконка «+» → «−» — CSS: вертикальна риска (`plus-bar*.svg`) згортається через `background-size`, у FAQ іконка піднімається з центру першого рядка до верху (`--acc-faq-icon-drop`). Геометрія в стані спокою не змінюється (закритий FAQ-рядок 90u, відкритий ≈187u; рядок товару 51u, крок 56u). Зміна фото на сторінці товару (клік по мініатюрі) — cross-fade (`product.js`, `--duration-base`).

Паралакс фото всередині контейнера (лише головна): `src/js/parallax.js` (динамічний import у `home.js` після `reveal.js`) + `src/styles/parallax.css`. Розмітка: `data-parallax` на контейнері (hero, `.brand-half`, `.tour-card__photo`, `.picker__bgs`), `data-parallax="soft"` — менший зсув для великих фонів (hero, фон picker); фото — прямий нащадок `<img>`. Фото розміром з контейнер; нейтральна точка (контейнер по центру в'юпорта, для hero — scroll=0) = зсув 0 і масштаб 1, тобто кадр збігається з макетом Figma і з `?parallax=off`. Для `.tour-card__photo` додано `data-parallax-bleed`: окремий горизонтальний масштаб `--parallax-sx = max(sy, 1 + 2/ширина)` (CSS `scale: sx sy`) — запас по 1px з кожного боку, бічні краї фото вкриті і при v = 0, і при субпіксельних зсувах. Рух односторонній: `translate` вниз на 0…`--parallax-range` (5%) / `--parallax-range-soft` (3.5%) від висоти контейнера, `scale` 1 + y/h від нижнього краю (transform-origin) закриває відкритий верхній край — порожніх країв нема; інерція `--parallax-lerp` (0.08/кадр) через rAF; активні лише контейнери, видимі в IntersectionObserver. `translate`/`scale` не конфліктують з `transform` hover-zoom і opacity reveal; layout не змінюється (висоти секцій ті самі). Вимкнення: `?parallax=off` (для автоматизованих перевірок, як `?reveal=off`) і `prefers-reduced-motion: reduce` — клас `.js-parallax` не ставиться, фото в статичній позиції. На каталозі/товарі не підключається.

Плавний скрол: `html { scroll-behavior: smooth }` у `src/styles/base.css` (поруч із `scroll-padding-top` = висота header, щоб якір не ховався під sticky-хедером). Діє на переходи за якорями (футер «Контакти» → `#contacts`, `#quiz`) і на програмний `window.scrollTo` без `behavior`. У `src/styles/reveal.css` у блоці `prefers-reduced-motion: reduce` стоїть `scroll-behavior: auto`. Інерційний скрол колесом не реалізовано (окреме рішення, без бібліотек і JS). Фільтри каталогу (`#gin`, `#calvados`) не є якорями: зміна hash не скролить сторінку.

## Область реакції контролів

Правило: **клікабельна й ховерабельна вся видима область контролу** (фон, рамка, плитка, відступи, іконка), не лише текстовий вузол. Фон/рамку/padding має нести сам `<button>`/`<a>` (display/width/height/padding на кнопці, не на обгортці). Якщо плитка — обгортка з кількома елементами (напр. `.select`: лейбл + значення + шеврон), кнопка отримує утиліту `.hit-area` (`src/styles/base.css`: `::after { position: absolute; inset: 0 }`, кнопка без `position`, тож розтяжка рахується від позиціонованої плитки), а hover/focus-стан плитки ставиться через `:has(.select__button:hover)`. Не робимо клікабельним те, що не кнопка (заголовки, підписи). Текст у `overflow: clip` для рядків із line-height меншим за текстовий бокс шрифта (`.catalog-nav__item`), щоб область одного рядка не накладалась на сусідній. Перевірка: puppeteer — сітка точок усередині видимого прямокутника через `document.elementFromPoint`, кожна точка має належати цьому ж елементу або його нащадку (скрипт-приклад: scratchpad `ca/audit.cjs`; не в репозиторії). Опис — `design-system.html`, розділ «Область реакції».

## Фокус-кільце, hover рядків, меню з клавіатури
- **Focus-кільце** — глобальне правило `:focus-visible` у `base.css`: `outline: var(--border-hairline) solid currentColor; outline-offset: var(--focus-offset)`. Для плиток-контролів із `.hit-area` (select) кільце малюється на `::after` кнопки (`.select__button:focus-visible::after`, `border-radius: var(--radius-select)`, ті самі колір/товщина/offset), тож обводить усю плитку з радіусом плитки; фон плитки додатково світлішає (`--color-select-bg-hover`). На пілюлі хедера (`.site-header__bar :focus-visible`, включно з випадним меню) колір кільця — `--color-beige` (а не currentColor): логотипи, меню, каталог, Кошик, підказати?, пункти й дві кнопки меню — контраст кільця до підкладки пілюлі ≈ 8:1 (≥ 3:1). Посилання футера мають `width: fit-content` — кільце не виходить за колонку. Hover/focus кнопок об'єму `.product-volume`: м'яка плашка `::before` (колір тексту × `--opacity-volume-hover` 0.1, виліт `--space-volume-hover-pad`, `--duration-fast`), неактивна додатково 0.4→1; вибрана лишається opacity 1. Кільце beige на зеленому тлі каталогу — контраст ≈ 9.4:1 (≥ 3:1).
- **Hover рядка акордеона товару** (`.acc--product`, лише `(hover: hover)`): фон `--color-hover-acc-product` (#E4E3D8, теплий світлий беж) через `--duration-fast`, без підкреслень; FAQ-рядок лишається на `--color-hover-faq`. **Крихти** (`.product-crumbs a`): hover/focus — `opacity: var(--opacity-crumb-hover)` (0.6), без підкреслення.
- **Кнопка «меню»**: відкритий стан (`aria-expanded="true"`) ходить на `--duration-fast` (плавно); короткий `--duration-focus` лише для `:focus-visible`. Анімація бургера: крайні смуги звужуються до `--scale-burger-bar` (0.6) зліва на hover/focus/відкритому меню, назад при виході; середня смуга не змінюється.
- **Меню з клавіатури** (`header-menu.js`): меню закривається, коли фокус виходить за межі кнопки + панелі (Tab з «замовити бочку» → «каталог», Shift+Tab з кнопки); Esc (слухач на `document`, діє з будь-яким фокусом, також коли меню відкрите ХОВЕРОМ і фокус на `body`; WCAG 1.4.13) закриває меню; фокус повертається на кнопку «меню», лише якщо він був у кнопці/панелі (клавіатурний сценарій), при ховері фокус не рухається; після Esc меню не відкривається знову, доки курсор не вийде з кнопки/панелі й не повернеться (`escaped` у `header-menu.js`); закріплення кліком теж закривається Esc.
- **Шрифти і CLS при холодному завантаженні**: `partials/head-fonts.html` (preload `crossorigin` для EB Garamond cyrillic+latin, Manrope cyrillic+latin, Cormorant latin — футер-wordmark) підключений на всіх сторінках; URL збігаються з `@font-face` у `fonts.css`, тож файл вантажиться один раз. Параметр `price="1"` (index, catalog, product, design-system) додає preload `eb-garamond-hryvnia.woff2` — піднабір (1,2 КБ, змінна вісь wght) лише зі знаком ₴ (U+20B4) з `eb-garamond-latin-ext` (114 КБ), оголошений у `fonts.css` ПІСЛЯ latin-ext/cyrillic-ext і тому перекриває їхній діапазон: ціни не чекають важкий файл і не міняють ширину при підміні шрифта; на сторінках без цін preload не додається (інакше консольне попередження «preloaded but not used»). Адаптивні fallback-шрифти (`Manrope Fallback` = Arial, `EB Garamond Fallback` / `Cormorant Fallback` = Times New Roman, окремо для кожної ваги): `size-adjust` (виміряно на укр. тексті) + `ascent/descent-override` (метрики веб-шрифта ÷ size-adjust) + `line-gap-override: 0` — до завантаження шрифта текст займає майже ті самі ширину й базову лінію (центрований текст не «їде», рядки не міняють висоту). Підключені в `--font-family-sans/-serif/-display` відразу після веб-шрифта; після завантаження вигляд не змінюється. Вимір (медіана/макс. по 25 холодних запусків, CPU 4×, кеш вимкнено, локальний сервер із затримкою шрифтів 250 мс) — див. звіт у комітах; ціль CLS ≤ 0.001.

## Вікова верифікація (age-gate)
Повноекранний світлий оверлей з карткою «Підтвердіть, що вам виповнилося 18 років» на КОЖНІЙ сторінці (index, catalog, product, about, faq, cart, offer, 404, design-system).
- **Підключення (без копіювання розмітки):** `<!--@include head-age-->` у `<head>` (inline-скрипт до першого paint: ставить `html.js` і, якщо вік підтверджено, `html.age-ok` — оверлей не блимає; плюс `<script type="module" src="/src/js/age-gate.js">`) і `<!--@include components/age-gate-->` одразу після `<body>`. Картка — `components/age-gate-card` (її ж показує design-system), кнопки — `components/btn-button` + нова контурна варіація `.btn--outline`.
- **Файли:** `src/styles/components/age-gate.css`, `src/js/age-gate.js`, токени — блок «Вікова верифікація» в кінці `tokens.css`.
- **Сховище:** ключ `ks_age_ok` = `{ok:true, ts}`. «Запам'ятати» увімкнено → `localStorage`, термін 30 днів (`days` у `partials/head-age.html`); вимкнено (за замовчуванням) → `sessionStorage` (між сторінками тієї ж вкладки не перепитує, нова вкладка питає). Недоступний storage (приватний режим) → try/catch, оверлей на кожній сторінці. «Ні» не зберігається.
- **`?age=ok`** — службовий параметр для тестів і скриншотів (як `?reveal=off`): ставить sessionStorage, оверлей не показується. Це НЕ безпека. `navigator.webdriver` ворота не обходить.
- **Діалог:** role=dialog, aria-modal, фокус-пастка, Esc не закриває, сторінка під ним `inert` + `aria-hidden`, скрол заблоковано через `html:not(.age-ok){overflow:hidden; scrollbar-gutter:stable}` (хедер не зсувається); при classic scrollbar (≈15 px) порожню смугу gutter fixed-оверлей не фарбує (вона поза viewport і малюється лише КОЛЬОРОМ фону html, картинка туди не виводиться), тому поки ворота показані, `html:not(.age-ok):not(.age-closing)` має `background-color: var(--color-age-gutter)` (= середній тон візерунка воріт: beige + 2% green, ±1/255; до виправлення смуга була кольору сторінки — зелена на каталозі/товарі); з початку закриття `age-gate.js` ставить `html.age-closing` і фон знімається (смуга знову кольору сторінки, без «залишку» ворота під час згасання); без смуги (overlay scrollbars) ефекту немає; для цього `viewport.js` міряє `getBoundingClientRect().width` html замість `clientWidth` (при gutter clientWidth включає порожню смугу). Без JS — повідомлення «Для перегляду сайту ввімкніть JavaScript» (ворота лишаються: безпечніше).
- Посилання в суцільному тексті підкреслені (виняток з правила «без підкреслень, крім футера»; одне спільне правило в `base.css`): юридичний текст воріт (`offer.html#rules`, `offer.html`), згода форми (`privacy.html`, `offer.html#rules`), повідомлення форми (`.contact-form__alert`, `.contact-success`).

### Як додати коктейль
1. Додати об'єкт у масив `COCKTAILS` у `src/data/cocktails.js` (порядок у масиві = порядок на сторінці). Поля — плоский текст без HTML:
   - `slug` — латиниця/цифри/дефіс, унікальний (якір `cocktails.html#slug`, префікс id табів);
   - `title` — назва; `original` — оригінальна назва (необов'язково);
   - `description` — 2–3 речення, до 320 знаків (зараз ≈200–210; довжини між коктейлями приблизно однакові);
   - `photos` — рівно 1 фото `{ src, alt, slot? }`: `src` — шлях від `public/` без початкового «/» (`assets/img/cocktails/<slug>-glass.webp`), квадратний кроп (≈1:1; рамка блоку ≈582×548u) з одним келихом і запасом навколо (фрейм блоку 581.67×547.67u, `object-fit: cover` по центру — келих по центру кадру із запасом ≥5% зверху й знизу); `alt` — опис кадру; `slot` — нотатка для `?slots=on`;
   - `ingredients` — `[{ name, amount }]`, `amount` рядком («50 мл», «2 деші», «за потреби»);
   - `steps` — 1–6 коротких кроків у наказовому способі (нумерація автоматична); `ingredients` — 1–7;
   - `serve` — `{ glass, garnish }` (вкладка «Подача»);
   - `product` — `slug` товару з `src/data/products.js` (картка каталогу праворуч); `productNote` — необов'язкова примітка, чому обрано цей напій;
   - `draft: true` — поки текст/фото не затверджені замовником.

**Порадник «Чому не зменшується».** Після кожної правки spacing/size/align Едіт заміряє bounding box вибраного елемента, його дітей, батька й сусідів до/після; якщо Δ=0, у панелі з'являється «Зміна не вплинула: <причина>». Типові причини: (1) `justify-content: space-between|around|evenly` — проміжок це розподіл вільного місця, `gap` лише мінімум (кнопка переходу на початок + gap); (2) діти з `min-width`/`flex-basis`/фіксованою шириною — розмір задано, gap його не міняє; (3) grid-доріжки `1fr`/фіксовані — gap забирає місце в доріжок, а не зсуває елементи; (4) `padding` батька й `margin` сусідів додаються до проміжку незалежно від gap; (5) margin collapsing (вертикальні margin сусідів зливаються, діє більший), `position: absolute|fixed`, inline-елемент (вертикальні padding/margin/height не діють); (6) `row-gap` у flex-ряду без `flex-wrap` — немає між чим; (7) `min-/max-height|width` тримають розмір.

**Колір, прозорість кольору й opacity (запит замовника «зміна кольору та опасіті по токенах колір системи»).** У панелі група «Колір» — окремі властивості вибору: `текст` (`color`), `фон` (`background-color`), `рамка` (`border-color`; доступна, лише якщо в елемента є рамка), `іконка` (SVG: `fill` або `stroke`; якщо іконка на `currentColor` — `color`; доступна для `svg` і елементів з `svg` усередині), та окремо `весь елемент (opacity)`.
- **Колір — лише токени `--color-*`** з `tokens.css` (палітра читається з `:root` динамічно, дублікати значень — аліаси; `--color-hover-*` виключено): сітка свотчів з назвою токена й hex, поточний токен підсвічено (зворотний пошук computed → токен, з урахуванням alpha), вибір застосовується миттєво як inline-накладка (`var(--color-…)`). Клавіатура: `←/↑` попередній, `→/↓` наступний токен, `Enter` — застосувати/підтвердити, `Esc` — скинути цю властивість (другий `Esc` знімає вибір), кнопка «↺ Скинути». Довільного hex/колорпікера немає; програмна спроба застосувати не-токенний колір відхиляється (`edit.setColorToken(el, prop, '#ff0000')` → `false`, «колір не з токенів системи — відхилено»), так само відхиляє API (`400`).
- **«Прозорість» = alpha кольору вибраної властивості, а не `opacity` елемента:** застосовується як `color-mix(in srgb, var(--color-токен) N%, transparent)` (текст → alpha `color`, фон → alpha `background-color`, рамка → `border-color`, іконка → `fill/stroke`); діти не змінюються, `opacity` елемента = 1. Кроки: токени `--opacity-*` системи першими (напр. `--opacity-disabled` 40%, `--opacity-logo-hover` 80%…), далі експериментальні 90/70/50/30/20% (пунктирні кнопки «експ.», ті, що збігаються з токеном, показані як токен), `100%` = без прозорості. `Shift+↑/↓` або `PageUp/PageDown` — крок прозорості, прозорість зберігається при зміні токена; без токена кольору прозорість не додається. `весь елемент (opacity)` — окрема вкладка з попередженням «разом з дітьми»; кроки лише `--opacity-*` і 1.
- **Контраст (інформаційно, не блокує):** для `текст`/`фон` панель і запис показують WCAG-контраст пари текст/фон з урахуванням alpha і шарів фону: AA 4.5, великий текст (≥24px або ≥18.66px bold) — 3; «НЕ проходить AA» підсвічується червоним. Є фон-зображення — значення орієнтовне.
- **Запис** `type: "span"` на сторінках lp (елемент усередині секції з `id` із `src/data/<сторінка>.js`): сервер додає `sourceData` (`src/data/<сторінка>.js`), `sourceKey` (id секції), `sourceField` (`cols` — елемент на всю ширину сітки секції, тож span = `cols` секції; `span` — вужчий елемент: span пункту/групи) і `sourceLine`. Хук друкує оркестратору: «ЗМІНИТИ ДАНІ: cols секції «tasting» у src/data/excursions.js:51: було 10 → стало 8». На не-lp сторінках (немає `src/data/<сторінка>.js` з таким id) поля не додаються, правка читається як раніше (`span` з `to.token`).
- **Запис** `type: "color"`: `target` (`text|background|border|icon`), `prop` (css-властивість), `from`/`to` = `{property, token, colorToken, value (hex), color (computed), css, alphaPct, alpha ("--opacity-…" або "50%"), alphaToken, alphaKind (none|token|experimental), alphaNearest {token, percent} (для експериментальних), label, contrast {ratio, need, pass, large, text}}`, `source`/`sourceLine` (перший `class=`/`id=` елемента в `partials/**` або `*.html`), `sourceCss` (`src/styles/….css:рядок` правила), `desc`, `note`, `shot`, `status`. `type: "opacity"` — `from/to = {property: 'opacity', token|null, value, css}`. Сервер приймає лише токени (`color`: `to.token` = `--color-*`, `to.css` = `var(--color-…)` або `color-mix(… var(--color-…) N%, transparent)`; `opacity`: `--opacity-*` або 1), інакше `400`. Хук друкує: `… color · url | селектор | «текст» | desc | було: … → стало: … | токен: … | властивість: background (фон; css background-color) | колір-токен: --color-beige (#DCDBCF) → --color-green (#223520) | прозорість кольору: 50% — експериментальне значення, потребує рішення: найближчий токен --opacity-liquid-back (45%) або новий | контраст текст/фон: … | source: … | css: …`; для токенної alpha — `прозорість кольору: 40% = токен --opacity-disabled`; для `opacity` — «opacity ВСЬОГО елемента разом з дітьми (не alpha кольору)».
- Приклад запису — `tool/edits.sample.json` (design-machine/09-edit-tool).

**Надіслані правки лишаються видимими до `done`.** Чернетки (`draft`) І надіслані (`open`, «надіслано · чекає виконання») з `edits.json` застосовуються як живі накладки на кожному завантаженні сторінки (також у новій вкладці/після Vite full-reload; не залежить від `sessionStorage`; збіг за шляхом без `?query`) — доки виконавець не змінить код і статус не стане `done`: накладки знімаються автоматично (опитування файлу ~4 с, при перезавантаженні `done` не застосовуються). Не подвоюється з уже застосованим кодом: якщо накладка не змінює computed-значення (або для `move` поточний порядок ≠ «було») — вона не ставиться. Відкликати: «×» у списку змін, `↶`/undo до оригіналу, «Скинути все» (видаляє із файлу і чернетки, і надіслані-невиконані) або `rv.py edits rm <id>`; «Очистити чернетки» чіпає лише `draft`. **Чому розмір не змінюється (діагностика Едіта, `sizeCause`/`explain`/`hintFix`).** Після кожної правки height/width Едіт заміряє геометрію; якщо вона не змінилась, у підказці названо КОНКРЕТНУ причину й дано кнопки дій. Також у панелі для height/min-height/width/max-width завжди показано «джерело розміру»: розтягнуто / фіксовано (значення) / N% батька / за співвідношенням сторін / за вмістом.

| Причина | Підказка | Кнопки |
|---|---|---|
| flex-grow>0 по головній осі (напр. `textarea` з `flex: 1` у колонці `.field`) | «висоту задає батько <селектор> (flex-grow: 1, flex-basis: 0%)…» | «Вимкнути розтягування (flex-grow: 0) і задати висоту» (ставить `flex-grow:0`, `flex-basis:auto` + висоту), «Перейти на батька» |
| stretch по поперечній осі flex або в комірці grid (`align-items`/`justify-items`: stretch або normal, власне значення auto) | «висоту/ширину задає батько <селектор> (align-items: stretch)…» | «Вимкнути розтягування (align-self: start / justify-self: start) і задати …», «Перейти на батька» |
| `min-height` тримає висоту | «min-height тримає висоту» | «Змінити min-height замість height» |
| aspect-ratio, `textarea` (`rows`, `resize`), `fieldset` | додаткове пояснення в підказці | — |

Записи дії — група `unstretch-<id>`: `align` (align-self / justify-self / flex-grow / flex-basis) + `size`. На cocktails (панель за вмістом, `align-items: start`) хибних підказок немає.

**Клавіші Едіт (оновлено після скарги «стрілки міняють падінг, а не позиції»):**

| Клавіша | Дія |
|---|---|
| `E` | увімкнути/вимкнути Едіт |
| `←` `→` `↑` `↓` (без Alt, режим «Значення») | змінити вибране значення (padding/margin/gap/розмір) на крок шкали токенів; `Shift` ×3 |
| `Alt` + `←` `→` | у БУДЬ-ЯКОМУ режимі: поміняти вибраний елемент місцями з **візуальним** сусідом ліворуч/праворуч (за bounding box у тому ж батьку, не за DOM-порядком) |
| `Alt` + `↑` `↓` | те саме по вертикалі (вище/нижче) |
| `M` | перемкнути режим «Позиція» ↔ «Значення»; у «Позиція» голі стрілки = swap. Великий індикатор у панелі («Режим: Позиція — стрілки міняють місцями» / «Режим: Значення — стрілки міняють відступ») і мітка в кнопці тулбара; легенда клавіш у тулбарі |
| кнопки панелі «Позиція» | «◀ поміняти з лівим» / «поміняти з правим ▶» / «▲ … верхнім» / «… нижнім ▼» + поточна позиція `N/M`, імена сусідів; ті самі swap |
| перетягування `⠿` | вставка перед/після сусіда (індикатор вставки) |
| `Ctrl/Cmd+Z`, `Shift+Ctrl/Cmd+Z` | undo / redo; `B` — до/після; `A` — «на всі такого типу»; `Enter` — текст; `Del` — прибрати; `[` `]` `Tab` — навігація; `Esc` — зняти вибір |

Move: у grid з явними доріжками swap переставляє й дітей, й **доріжки `grid-template-columns`** (ширина йде разом з елементом: слайдер лишається 4 колонки, текст — `minmax(0,1fr)`); у flex — inline `order`; у звичайних блоках — DOM-порядок. Після переміщення: коротка FLIP-анімація (280 мс) і підсвітка «2 → 1» на кожному зсунутому елементі, у панелі — «Було … → Стало … Доріжки …». Запис `move` має `tracks {mode, before, after, beforeU, afterU, token, orderBefore, orderAfter}` та `source` («поміняти порядок у розмітці (partial) і порядок доріжок у токені --grid-…») і `restore.perm/gtc/orders` для відновлення. Панель угорі: «↶ Скасувати останню», «Скинути все (N)» (з підтвердженням), «Очистити чернетки» (видаляє лише `draft`, не `open/done`), перемикач «Відновлювати чернетки після перезавантаження» (за замовчуванням так; вимкнено → чернетки лишаються у файлі й показуються як «не застосовано», кнопка «Застосувати зараз»). Лічильник у тулбарі: «Едіт E · N правок». Надійність запису: upsert за id клієнта (`POST /edits {id}`), debounce 150 мс, повтори при помилці, `keepalive`-flush на `beforeunload`/`pagehide`/`vite:beforeFullReload`; автоматично з файлу видаляються лише чернетки.

## QA-набір
Спільні автоперевірки в `tools/qa/` (puppeteer-core + системний Chrome, чистий профіль на кожен запуск, без pkill). Документація, формат звіту, `check-ds.allow.json`, як додати перевірку — `tools/qa/README.md`.
```
npm run qa                       # smoke на 1920: check-ds (static) + links + hscroll + states (~3 хв)
npm run qa:full                  # 1200/1440/1920 × dpr 1,2 × classic+none: + check-ds dynamic, arch, cls
npm run qa:check-ds              # S1–S11 статичні + D1–D19 у браузері (-- --static-only | --dynamic-only | --rules S4,D5)
npm run qa:links | qa:states | qa:arch | qa:cls | qa:hscroll
npm run qa:resp                  # адаптив: R1 hscroll, R2 touch ≥44, R3 текст у межах, R4 шрифт ≥11, R5 перетин тексту, R6 ключові елементи/картинки (320…3440; docs/responsive.md)
npm run qa:grid                  # D12: блоки на межах 10 колонок (1200/1440/1728/1920)
npm run qa:d18                   # D18: горизонтальний зазор великих блоків: product, cocktails і cart 5u (gap5-pages), решта 40u
npm run qa:d19                   # D19: hero без оверлея (єдиний виняток — hero.fade)
npm run qa:header                # D15: шапка / меню
npm run qa:img-contrast          # D14: контраст тексту на фото по літерах (+ профіль parallax=on для barrels #price)
npm run qa:hero-btn              # кнопка hero: позиція/тон на lp-сторінках
npm run qa:lp | qa:lp-stack | qa:lp-cols   # контракт шаблону lp (схема, порядок секцій, cols/pad)
npm run qa:overlay-grid          # dev-оверлей «Сітка (G)» = сітка tokens.css
npm run qa -- --url https://mak-nw.github.io/kraftspirits-brand/    # живий сайт (за замовч. http://localhost:5200/)
```
Загальні аргументи: `--url`, `--widths`, `--dpr`, `--scrollbar classic|none|both`, `--pages index,catalog,"product?id=gin-yasnyi"`, `--json`, `--out`. Код виходу 0/1/2. Службові параметри `?age=ok&reveal=off&parallax=off` додаються самі.

## Сітка 10 колонок (рішення замовника, 16.10.2026: «весь сайт на 10 колонок»)

Єдина сітка сайту — **10 колонок** (було 12): колонка 115.42u і зазор 40u без змін, ширина сітки `--grid-w` = 1514.2u, поле від краю вікна `--grid-margin` = 202.9u. Токени `--grid-span-11/12` прибрано. Медіа за рамками колонок (повноекранні фони, hero-фото, фонові зображення секцій, фото-половини брендів на головній) лишаються на всю ширину вікна. Розкладки: пари великих блоків (зазор 5u) — 5+5 (фото | панель товару, картки брендів, formats, offers), 7+3 (кошик | підсумок), 6+4 (оформлення), 4+6 (контакти, «Наша локація»); меню кабінету 3 + вміст 7; картки каталогу — 4 рівні блоки по 348.55u (`--size-card-cat2-w`, арка перебудована під 336.55u); заголовки лишаються 4 колонки, центровані блоки на 6/8 колонок — по центру (3–8 / 2–9). Header: пілюля = колонки 1–10, усередині гнучкі ліва група | логотипи по центру | права група. Footer: Меню 1–3, Каталог 4–6, Контакти 7–9, юридичні посилання стовпчиком у 8–10. Деталі — `design-system.html#grid`, `docs/page-template.md`, `tools/qa/README.md`.
