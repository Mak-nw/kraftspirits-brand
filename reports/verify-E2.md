## Дефекти за серйозністю

**Середній (FIX)**
1. Сервер не гарантує «лише токени»:
   - `POST /edits` з `restore.value:'#ff0000'` приймається (201). Клієнт при reload застосує `restore.value` як inline, тож не-токенний колір потрапляє на сторінку. `restore` не валідується.
   - Upsert за існуючим id без `type` (або з `type:'spacing'`) оминає `tokenError`: `to.token:'#ff0000'` записано (200).
   - `color-mix(... 37% ...)` і `1.2.3%` приймаються (будь-який відсоток, UI лише кроки).
   - Виправлення: валідувати `restore.value`/`restore.css` для color/opacity; у upsert брати тип із наявного запису; перевіряти відсоток проти кроків.
2. Хибний hex після alpha: `to.value` = `#DBDBCF` для beige 50% (токен `#DCDBCF`) через округлення canvas. Хук/rv показують «--color-beige (#DBDBCF)» (ім'я токена вірне, hex на 1 одиницю невірний). Брати hex з rgb токена без alpha.

**Низький**
3. Порядок кроків alpha не «токени першими»: відсортовано за відсотком (100, 90 експ., 80 ток., 70 експ.…); README стверджує «першими». Експериментальні позначені коректно (90/70/50/30/20).
4. ↑/↓ в кольорі: ↑ = наступний токен, ↓ = попередній, хоча підказки й README кажуть «←/↑ попередній, →/↓ наступний» (←/→ вірні).
5. Повернення стрілками до вихідного токена лишає inline `background-color: var(--color-beige)` (запис видаляється, стиль лишається). Esc/«Скинути» чистять правильно. Залишок перекриває код до reload.
6. Скидання менш ніж за 150 мс після зміни дає 404 на DELETE у консолі (запис ще не створено); не впливає на дані.
7. Конфіг-приклад без `opacity`; опитування done зупиняється у прихованій вкладці (`document.hidden`).

Нових візуальних елементів у проєктних сторінках немає (перевірявся лише dev-інструмент). Без дублювання компонентів. Скрін alpha 50%: панель стає прозорою, показує зелений фон сторінки, текст і таби непрозорі; панель «Едіт» у 900px висоти тісна.
