## 4. Ручний аудит поза автоправилами
Метод: інвентар computed-значень усіх видимих елементів і їх `::before/::after` на 21 сторінці при 1440 (`border*`, `border-radius`, `box-shadow`, `outline`, `filter`, `backdrop-filter`, `mask`, `clip-path`, `background-image`, `opacity`, `transform` псевдоелементів, `text-decoration`, кольори `color/background/border/outline`) і порівняння з тим, що є на `design-system.html`.
- **(а) «Це є в DS?»** Значень, яких немає на сторінці DS, знайдено 3 типи і всі пояснені: (1) нативна `input[type=text]` (honeypot `#contact-website` у feedback, `visually-hidden`, `clip-path: inset(50%)`) — невидимий; (2) радіуси `50% 50% 0 50%` (маркер-«крапля» карти) і `3.75px 3.75px 0 0 / 0 0 3.75px 3.75px` (кнопки зуму карти у групі) — описані в DS текстом (розділ «Контакти», токени `--size-map-*`), але статичного демо немає (жива карта потребує WebGL) — залишено як є, розкриття додано до списку «не перевірено»; (3) прохідний `opacity 0.997` — кадр переходу активної вкладки каталогу. Решта (рамки 1px/3px/4px, радіуси 5u/10u/33.75/45u, арка 50% 50% 0 0, маски іконок і арки, `invert(1)` стрілок, `blur` пілюлі header і меню, ромб-чип через `linear-gradient`+rotate, галочка чекбокса, плюс/мінус акордеона) — є на DS (Радіуси та рамки / Компоненти / Стани). Тіней немає, окрім 1px-кільця помилки поля (`.field.is-invalid`, прописано в DS).
- **Кольори:** усі computed-кольори `color/bg/border/outline` на всіх 21 сторінці дорівнюють значенню якогось токена (42 різних колірних значення) — «чужих» 0 (окрім нативного honeypot-input).
- **Шрифти:** `D13` 0 порушень на 168 сторінко-ширинах (4232 типи вузлів); `S11` 0 (власних font*/line-height/letter-spacing/text-transform поза base.css немає).
- **Відступи/радіуси:** `S2` 0; сирих `border-radius` поза токенами немає (крім `50% 50% 0 0 / var(--lp-rise)` арки шаблону lp, `--header3-radius`); em-відступи лише оптичні поправки (`--lp-*-optic`).
- **(б) Дублі компонентів.** Знайдено і прибрано: `.feedback-window` повністю дублювало `.contacts-panel` (beige, рамка 5u кольору панелі, радіус 10u, pad 50u, min-height = фрейм екрана; значення токенів ідентичні) → розмітка `class="contacts-panel feedback-window"`, власні декларації й токени `--space-feedback-pad`/`--size-feedback-window-min-h` видалено; computed до/після — 0 піксельної різниці сторінки feedback. Розглянуто й ЛИШЕНО (різна візуальна відмінність, злиття змінило б вигляд — потрібне рішення замовника): `.product-panel` (рамка кольору акценту бренду, `--radius-product-frame`, свій padding) — окремий компонент товару; три «рядки з hairline»: `.lp-offer__fact` (flex space-between, `--color-line-soft`), `.cocktail__specs dt/dd` (grid, `--accent-line`), `.cocktail__step` (`--color-line-soft`) — близькі родичі, кандидат на єдиний компонент; `nav-cell--fill` ≈ `btn--beige` (різні розміри/радіуси за макетом хедера).
- **(в) Стани.** Перевірено `hover` / `focus-visible` / `active` примусово (CDP) для всіх інтерактивних елементів 11 сторінок: `focus-visible` змінює вигляд усюди (поза демо-елементами з примусовими класами). `hover` без зміни на самому елементі: логотипи header (hover спільний на групу `.site-header__logos`, прописано в DS), `select__button` (hover на `.select` — плитка), `summary` акордеонів (hover на батьківському `details`), `cocktail__zoom` (прозора кнопка зуму), канвас карти. `active` визначено лише для кнопок/nav-cell/стрілок (матриця станів DS); для посилань, чіпів, вкладок, полів `active` не задано — нового візуального стану без погодження не вводив.
- **(г) Застарілі коментарі/документація.** `tokens.css:118` (`--radius-none`: «картки, FAQ — прямі кути» → лише зовнішня рамка `.btn`; `.acc--faq` = `--radius-btn`); DS: розділ «Радіуси та рамки» (підписи токенів, нова демо-коробка `--radius-panel`, речення про тіні), рядок `nav-cell--ghost` у таблиці станів, примітка про підкреслення в «Віковій верифікації», опис вікна форми; README (вікно форми, підкреслення); `tools/qa/README.md` (S4, D6, D7); `reports/legal-placeholders.md` — додано розділ «Як сторінки виглядають зараз» (світла вертикальна верстка, колонки 4–9, h1 + одна кнопка, плейсхолдери видно як є), звірено номери пунктів плейсхолдерів із `src/data/legal.js` (збігаються). **`CLAUDE.md`**: твердження «FAQ — прямі кути» там відсутнє (було лише в tokens.css і DS); рядок про підкреслення оновлено (виняток для посилань у суцільному тексті), але файл у `.gitignore:28` — зміна лежить локально й НЕ закомічена.

## 7. Що не перевірено
- Safari/Firefox, справжній touch, справжній hover (CDP `forcePseudoState`; `(hover: hover)` обмежує частину правил).
- Ширини поза 1200/1440/1728/1920 (за правилом проєкту планшети/телефони не верстаються); dpr ≠ 1 — лише arch/ink (як у наборі).
- Жива карта (MapLibre) у headless: плитки/кнопки зуму/маркер перевірені лише за computed і D6, без постійного скріну в обох збірках.
- `:active` для посилань/чіпів/вкладок/полів (немає в DS; рішення замовника).
- `CLAUDE.md` не в git (ігнорується) — правка не потрапила в коміти.
- Об'єднання «рядків з hairline» і інші злиття з видимою зміною (потрібне рішення замовника).
- Відтворюваність: dev-сервер у проєкті перезавантажує сторінки при записі в `tools/qa/.out` (профілі Chrome) — під час прогонів це давало випадкові хибні «links 21», «чекбокса не знайдено», `ERR_CONNECTION_REFUSED`; фінальні числа знято на сервері з вимкненим вотчером цієї теки (`--out` у scratch). Варто додати `server.watch.ignored` у `vite.config.js` (не робив — поза межами задачі).
- Тестова оцінка «інвентаря» робилась на 1440; на 1200/1920 тільки автоправила check-ds.
