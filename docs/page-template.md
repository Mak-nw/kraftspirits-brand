# Шаблон посадкової (продажної) сторінки — `lp`

Сторінки на шаблоні: `barrels.html` (Ф'ючерсні бочки, тема `barrels`), `excursions.html` (Екскурсії та дегустації, тема `excursions`), `b2b.html` (B2B та Івенти — прототип, дві вкладки, тема `excursions`). Нова сторінка з'являється від одного файлу даних — див. «Як додати сторінку».

**Сторінка = ДАНІ + МЕДІА + ТЕМА.** Розмітка, стилі блоків і логіка — спільні. Різниця між сторінками — лише в даних (`src/data/<сторінка>.js`), медіа (шляхи й назви ілюстрацій у даних) і темі кольорів (`src/styles/themes/<тема>.css`).
Адмінка (WP/ACF/Gutenberg) = ті самі поля, що в схемі нижче, один-в-один: назва поля, тип, обов'язковість, ліміт довжини, допустимі значення, перехресні правила. Єдине джерело правил — `src/data/lp-schema.js`: з нього збірка перевіряє дані, з нього ж генерується JSON Schema (`docs/page-template.schema.json`).

| Що | Де |
|---|---|
| Схема даних + перевірка (збірка падає з поясненням) | `src/data/lp-schema.js` (`SCHEMA`, `RULES`, `PAGE_RULES`, `validatePage`, `lpView`); файлові перевірки — `tools/lp-files.mjs` |
| JSON Schema (для адмінки/валідаторів) | `docs/page-template.schema.json` — генерується: `node tools/lp-schema-json.mjs` (з тих самих правил, що й збірка) |
| Контрактна перевірка «фронт ≡ адмінка» | `npm run qa:lp` (`tools/qa/lp-contract.mjs`) |
| Дані сторінок | `src/data/barrels.js`, `src/data/excursions.js` |
| Тема (лише ролі кольорів) | `src/styles/themes/<тема>.css` |
| Кадр фото й оптика чорнила конкретної сторінки (необов'язково) | `src/styles/pages/<сторінка>.css` (`body.lp-page--<slug>`) |
| Розмітка сторінки / секцій | `partials/lp/page.html`, `partials/lp/<type>.html` (+ дрібні: `head`, `layer`, `step`, `group`, `tile`, `offer`, `route` …) |
| Ілюстрації-медіа (обираються в даних) | `partials/media/<вид>-<назва>.html` + `src/styles/media/<вид>-<назва>.css` (вид: `scene` · `engraving` · `cellar`) — реєстр нижче |
| Стилі | `src/styles/lp.css` (блоки), `src/styles/lp-media.css` (загальне для ілюстрацій), токени — блок «Шаблон посадкової сторінки» в `tokens.css` |
| Логіка | `src/js/lp.js` (лічильники, стани гравюри, `?slots=on`, FAQ, мапа — лише якщо відповідна секція є) |
| Збірка/dev | плагін `lp-auto` (`tools/vite-plugin-lp.mjs`): виявлення сторінок, `<slug>.html`, підключення CSS, ліниві перевірки; рушій partials — `tools/html-partials.mjs`; демо-секція в DS — `<!--@lp сторінка id-->` |
| Дизайн-система | `design-system.html#page-template` |

## Як додати сторінку

1. `src/data/<slug>.js` — `export const <slug> = { slug, theme, metaTitle, metaDescription, sections: [...] }` за схемою нижче. `<slug>` = ім'я файлу (`a-z0-9-`); експорт називається як slug, а для slug з дефісом — у camelCase (`my-page` → `export const myPage`).
2. `src/styles/themes/<theme>.css` — клас `.theme-<theme>` з ролями `--lp-*` (лише токени палітри DS; таблиця ролей — нижче). Можна взяти наявну тему (`theme: 'excursions'`) — тоді цей крок не потрібен.
3. **Більше нічого.** `<slug>.html` (один рядок `<!--@page <slug>-->`) плагін створює сам при першому запуску — файл треба закомітити; CSS тем/ілюстрацій/сторінок підключається автоматично (`/*@lp-auto*/` у `main.css`); реєстру в `vite.config.js` немає. Новий файл даних у запущеному `npm run dev` перезапускає сервер сам.
4. **Вручну лишається лише навігація:** посилання на сторінку в `partials/header.html` / `partials/footer.html`.

Якщо сторінці потрібен власний кадр фото в секції `offers` або оптична поправка чорнила під конкретний текст — `src/styles/pages/<slug>.css` (за зразком `pages/barrels.css`); інакше файл не потрібен (оптика типово 0, кадр — центр).

Помилка даних: **збірка** падає одним повідомленням `lp: <slug>.sections[2](how).items[0].title: довжина 31 > 25 знаків`; у **dev** помилка видна лише на своїй сторінці (оверлей Vite), інші сторінки працюють.

Тексти: будь-яке поле приймає видимий плейсхолдер `[потрібно уточнити]`. Порожнє необов'язкове поле (`''`, `null`, відсутнє, порожній масив) — блок не показується.
HTML у полях не приймається (усе екранується); нерозривний пробіл — символ U+00A0. Довжина — у кодових точках (nbsp = 1). У текстових полях `%contacts.<ключ>%` лишається текстом (підстановка контактів діє лише в полях-посиланнях).

| Поле | Тип | Обов. | Ліміт / значення | Що це |
|---|---|---|---|---|
| `slug` | id (`a-z0-9-`) | так | = ім'я файлу даних | ім'я файлу `<slug>.html` |
| `theme` | id | так | є `src/styles/themes/<theme>.css` | тема: `body.theme-<theme>` |
| `tone` | enum | ні | `teal` · `green` · `gold` · `light` · `beige` | тон основних кнопок DS (`.btn--<tone>`) на світлому/фото; типово — роль `--lp-tone` теми |
| `metaTitle` | текст | так | ≤ 70 | `<title>` |
| `metaDescription` | текст | так | ≤ 200 (пошук показує ≈ 155) | `<meta name="description">` |
| `sections` | список | так | 1–20; перша — `hero` і лише вона | секції в порядку показу |
| `tabs` | список | ні | 2–3: `key` (id, = hash `#key`), `label` (≤ 20, слово ≤ 16), `start` (id hero-секції) | вкладки верхнього рівня, див. «Вкладки» нижче |
| `tabsLabel` | текст | ні | ≤ 40; лише з `tabs` | `aria-label` перемикача вкладок |

## Вкладки верхнього рівня (`tabs`; сторінка `b2b`)

Сторінка може складатися з кількох «під-сторінок» з власним hero й блоками (рішення замовника: «B2B та Івенти» — дві вкладки, кожна зі своїм заголовком-закликом). Секції лишаються ПЛОСКИМ списком `sections`; вкладки задаються окремо: кожна вкладка починається з hero-секції, `tabs[].start` = `id` цієї hero, і триває до наступного старту (вкладки в `tabs` — у порядку секцій; перша стартує з першої секції; типово відкрита — перша). Приклад — `src/data/b2b.js`:

```js
tabsLabel: 'B2B та Івенти',
tabs: [ { key: 'b2b', label: 'B2B', start: 'b2b-hero' }, { key: 'events', label: 'Івенти', start: 'events-hero' } ],
sections: [ { type: 'hero', id: 'b2b-hero', … }, …секції B2B…, { type: 'hero', id: 'events-hero', … }, …секції Івентів… ],
```

* **Розмітка** (`partials/lp/tabbar.html`, `tabbar-tab`, `tabpanel-open`, `tabpanel-close`, `tabs-close`; службові блоки вставляє `lpView` — у даних їх немає): компонент DS `.tabs` (той самий, що на cocktails.html: `role=tablist/tab/tabpanel`, вигляд вкладки `.product-volume`, `src/js/tabs.js`) — смуга-перемикач (кімната `deep`, під fixed-пілюлею header, по центру) над панелями; кожна панель = hero + секції вкладки. Неактивна панель прихована (`display: none`, `.js .tabs__panel:not(.is-active)`); без JS видно всі панелі підряд. Дві `<h1>` у DOM, видима одна.
* **Hash:** `data-tabs-hash` на корені + `data-tab-key` у вкладок — `#<key>` в адресі відкриває вкладку (`/b2b.html#events`), клік і ←/→/Home/End пишуть hash (`replaceState`, без стрибка), `hashchange` перемикає. Без hash — перша вкладка. Нова логіка — лише ці рядки в `src/js/tabs.js` (повторно використано наявний модуль) і виклик `initTabs` у `src/js/lp.js`.
* **Стилі:** `lp.css`, блок «вкладки верхнього рівня»: лише відступи токенами (зона header + `--space-20` над/під перемикачем) і центрування; нових кольорів, ліній і компонентів немає.
* **Правило** `tabs-start-hero` (нижче). `id` секцій і `key` у списках унікальні в межах УСІЄЇ сторінки (префіксуйте `id` вкладкою: `b2b-…`, `events-…`); якір `#id` у кнопках може вести на секцію іншої вкладки лише з перемиканням вручну — для переходу між вкладками використовуйте hash.
* **JSON Schema** (`docs/page-template.schema.json`): поля `tabs`/`tabsLabel` описані; з `tabs` hero дозволено і далі першої секції (умова if/then); збіг `start` з `id` hero й унікальність — лише збірка (правило `tabs-start-hero`, `expressed: false`). Контроль — `npm run qa:lp` (блок «tabs»).
* Без `tabs` усе працює як раніше (barrels, excursions не змінюються).

## Спільні поля секції

Кожен тип бере лише ті з них, що його partial справді показує (поле в схемі ⇒ воно є на сторінці; це перевіряє `qa:lp`). Нижче в таблицях типів — що саме приймає тип.

| Поле | Тип | Обов. | Ліміт / значення | Що це |
|---|---|---|---|---|
| `type` | enum | так | `hero` `layers` `steps` `compare` `formats` `tiles` `offers` `card` `place` `faq` | тип блоку |
| `id` | id | так (крім hero) | унікальний на сторінці | якір (`#id`) |
| `room` | enum | ні | `warm` · `deep` · `paper` (типово — за типом) | «кімната»: тло секції; кольори кімнат задає тема |
| `join` | так/ні | ні | | продовжити кімнату попередньої секції (без межі, лише повітря 150u) |
| `pad` | число | ні | крок шкали простору DS: `20` · `30` · `40` · `50` · `70` · `100` (`--space-<крок>`); не для `hero`; не разом з `loose`/`join`/`stack` | **верхній і нижній padding секції** замість типових 177u (рішення замовника d360474e: `#shop` — `pad: 40`). Секція-сусід з `join` має перевагу над своїм краєм (нижній відступ — join). **`pad` і `stack`**: якщо за секцією з `pad` іде секція-стек, її нижній відступ = 0 (клас `lp-sec--stack-next`), а зазор до стекової секції — 5u, як між `tour-card` на головній (рішення замовника 5d981ca1: «відступ менше, логіка як на головній»; на `#shop` — `pad: 40` лише зверху, зазор до «Нашої локації» 5u) |
| `stack` | так/ні | ні | лише `card` і `place`; не разом з `room`/`join` | **стек великих блоків**: секція стоїть під попередньою `card`/`place` у ТІЙ САМІЙ кімнаті (тло береться з попередньої), без верхнього відступу секції, зазор між блоками `--grid-gap-panels` (5u) — як `tours` наприкінці головної |
| `kicker` | текст | ні | ≤ 25 | надзаголовок |
| `title` | текст | так | ≤ 60 (`card` ≤ 36) | заголовок H2 (у hero — H1) |
| `lead` | текст | ні | ≤ 320 (hero ≤ 160) | лід під заголовком |
| `caption` | текст | ні | ≤ 120 | дрібний підпис під лідом (`.t-caption`) |

Які спільні поля приймає тип: `hero` — `id` (необов'язковий), `title`, `lead` (без `room`, `join`, `pad`, `stack`, `kicker`, `caption`); `layers`, `steps`, `compare`, `formats`, `tiles` — усі, крім `stack`; `offers` — усі, крім `caption`, `stack`; `card` — без `lead`, `caption` (+ `stack`); `place` — без `caption` (+ `stack`); `faq` — лише `id`, `room`, `join`, `title` (кікера, ліду й підпису немає).

**Ширина заголовка `titleCols`** (hero, `layers`, `steps`, `compare`, `formats`, `tiles`, `offers`): `4` (типово) або `6` — виняток за рішенням замовника (d0234bbc, 58f675f7, 28fcde83: «в два рядки»): `.heading-wide` = `--grid-span-6` (по центру, колонки 3–8), рядки рівні, слова не рвуться; перевірка D17 допускає 6 колонок лише з цим класом. Без поля — правило нижче.

**Заголовки секцій — 4 колонки по центру.** `title` кожної центрованої секції (H1 hero і H2 шапок `layers`/`steps`/`compare`/`formats`/`tiles`/`offers`) — display-роль `.t-hero`/`.t-h2` у блоці шириною `--size-heading-w` (= `--grid-span-4`, 581u на 1920): клас `.heading-center` (base.css), рядки рівні (`text-wrap: balance`), слова не розриваються. Довгий заголовок просто переноситься на 2–4 рядки; найдовше слово має вміщатись у 4 колонки (≈ 9–11 літер великими на 1200). Заголовок усередині панелі (`card`, `place`) лишається лівим краєм. Перевірка — `check-ds` D17.

**Сітка і ширина вмісту секції: `cols`.** Сторінки lp стоять на ЄДИНІЙ сітці сайту з **10 колонок** (рішення замовника 16.10.2026, «весь сайт на 10 колонок»: колонка 115.42u і зазор 40u без змін, ширина сітки `--grid-w` 1514.2u, поле від краю вікна 202.9u). Повноекранні фони кімнат, hero-фото та фонові зображення секцій («Ціна») лишаються за рамками колонок на всю ширину вікна; в 10 колонок вписано лише вміст. Поле `cols` (рішення замовника 6e388014, d632dcfb) — кількість колонок, яку займає **вміст** секції (сітка плиток / панелей / груп / шарів / питань): контейнер завширшки `--grid-span-<cols>` по центру (8 — колонки 2–9, 6 — колонки 3–8; зовнішні краї лежать на межах колонок, D12). Шапка секції (кікер, H2, лід) лишається за своїми правилами: H2 — 4 колонки по центру. **Без поля — 10 колонок (уся сітка), `cols: 10` не задають** (раніше «10 колонок» означало 10 з 12 і давало вужчий контейнер; тепер це повна ширина, тож у даних сторінок поля немає). Допустима лише ПАРНА кількість колонок ≤ 10 (по центру краї мають лежати на межах колонок); 12 і значення > 10 відхиляються схемою.

| Тип | Дозволені `cols` | Пункти всередині |
|---|---|---|
| `layers` | 6 · 8 · 10 | n пунктів (2–6) = **n рівних блоків** контейнера із зазором колонок 40u: 2 і 5 лягають на колонки, 3, 4, 6 — рівний поділ (4 на 10 колонок — по 348.55u; краї ряду на колонках 1 і 10; правило D12 «рівний поділ»); колишнього правила «кількість пунктів ділить `cols`» (cols-items-divide) більше немає |
| `compare` | 8 · 10 | сума `span` груп = `cols` (`span` 2–8; бочки: 3 + 7) |
| `formats` | 8 · 10 | дві панелі по `cols` / 2 колонок (5 + 5), шов — зазор колонок 40u (зовнішні краї — на колонках контейнера) |
| `tiles` | 6 · 8 · 10 | якщо кількість плиток ділить `cols` — плитка = `cols` / кількість колонок; інакше (4 плитки на 10 колонок) — **n рівних блоків** контейнера із зазором колонок `--grid-gap` (40u): діаметр кола = (ширина контейнера − (n − 1) · зазор) / n; краї ряду — на колонках контейнера, внутрішні шви — за схемою «рівний поділ» (D12) |
| `offers` | 8 · 10 | n панелей (1–3) = **n рівних блоків** контейнера із зазором колонок 40u (дві — 5 + 5 колонок, шов посередині; три — рівний поділ) |
| `faq` | 6 · 8 · 10 | заголовок групи — колонки 1–3 контейнера, рядки питань — решта (від колонки 4) |
| `steps` | 8 · 10 — **лише з `deck: true`** | ширина колоди карток (кожна картка = `cols` колонок; текст картки — 4 колонки); варіант з аркою — фіксована композиція (арка колонки 1–4, колонка 5 порожня, кроки колонки 6–10), `cols` не приймається |
| `card`, `place`, `hero` | — (поле не приймається) | фіксована композиція (панель `tour-card` 629u: фото 4 колонки + ½ зазору; панель 4 колонки + ½ зазору і мапа 6 колонок; фото на весь екран) |

Лише **парні** значення: контейнер по центру з непарним числом колонок мав би краї посередині колонки (D12). Мінімум залежить від типу — це виміряна ємність текстів; нижче збірка відхиляє значення з поясненням. Умовне «від колонки 1 / вирівнювання start» не реалізовано (`align`/`from` — окреме рішення: H2 4 колонки по центру сторінки не лягає на колонки при непарних зсувах).

## Типи секцій і їх поля

### `hero` — перший екран
Фото на весь екран без оверлея (єдиний виняток — градієнт `fade`, нижче), H1 `.t-hero` (4 колонки по центру), лід `.t-desc`, кнопка `.btn--<tone>`. Колір тексту — роль теми `--lp-hero-ink` (контраст на фото міряти піксельно, D8/D14). **`panel: true`** — текст hero (H1, лід, кнопка) стоїть у світлій панелі DS `.contacts-panel` по центру (6 колонок, 4–9), фото лишається чистим (без оверлея, градієнта, тіні); колір тексту тоді — роль панелі (`--color-green`), а не `--lp-hero-ink`. Обирайте `panel`, коли кадр не має вільної зони під текст (контраст на фото не проходить жодним кольором); опція за замовчуванням вимкнена: на екскурсіях замовник відхилив панель (коментарі 5db5d797, 02cd307d) — там замовник замінив це градієнтом (`fade`, нижче).

**`fade: green | teal | brown` — градієнт поверх фото знизу вгору** (рішення замовника 53422015: «знизу зелений 100%, уверх 0%, текст посунемо вниз»). Скрол — CSS `position: sticky` без JS: картка *i* прилипає на `--offset-lp-deck-top` (під пілюлею header) + *i* × `--space-lp-deck-peek` (70u), наступна наїжджає на попередню, від кожної попередньої видно верхню смужку 70u; після останньої картки колода відходить угору цілою (смужки не «схлопуються»), секція закінчується звичайно. | `slug-matches-file` | файли | `slug` = ім'я файлу даних | ні |

Також у самій схемі (виражено в JSON): кількість пунктів `layers` 2–6, `tiles` 2–6, `offers` 1–3 (n рівних блоків контейнера, див. «Сітка і ширина вмісту секції»; правила «ділить 12» більше немає); посилання — лише `#якір`, `/шлях`, `https://…`, `tel:`, `mailto:`, `%contacts.ключ%`, `сторінка.html[?…]` (без `javascript:` і `//host`); слово без пробілу ≤ 30 знаків (кнопки ≤ 16); `card.img` — під `/assets/img/`; `hero.id` може бути порожнім.

## Відкладено / обмеження

- **Мапа `place`** бере координати з `src/data/contacts.js` — різні локації на різних сторінках неможливі без окремого поля `lat/lng/zoom` і зміни компонента мапи (`components/contacts-map` + `contacts-map.js`).
- **Ілюстрації** (`scene-barrels`, `engraving-barrels-head`, `cellar-barrels`) під сюжет бочок; загальної бібліотеки ілюстрацій немає. Іконки `barrels-*` — теж малюнок під бочки (вибір вільний).
- **Меню/футер** — посилання на нову сторінку додається вручну (`partials/header.html`, `partials/footer.html`).
- **Кадр і оптика** сторінки — файл `pages/<slug>.css`, прив'язаний до `id` секцій і `key` елементів; у даних як поля адмінки їх немає (кадр — властивість фото; нове фото з іншим кадром = рядок у файлі сторінки).
- **Ємність по ширині тексту** виміряна для звичайного регістру (слова українською); ВЕЛИКІ літери («ЩЩЩ…») ширші — межі не гарантують вміщення суцільного ВЕЛИКОГО тексту (hscroll при цьому не виникає: слова переносяться).

## Перевірки

- `npm run build` — перевірка даних усіх сторінок (падає з поясненням); `npm run qa:lp` — контракт «фронт ≡ адмінка» (у т. ч. `hero.panel` і `stack`: правила й видимий ефект); `npm run qa:lp-stack` — геометрія в браузері: тло й зазор 5u стека, панель hero (центр, 6 колонок, без оверлея) + позитивні контролі;
- `npm run qa:check-ds -- --pages barrels,excursions --rules D8,D13,S11,D1,D2,D12 --widths 1200,1440,1728,1920 --scrollbar none` (колір/типографіка/сітка; заголовки 4 колонки — `--rules D17`), `qa:hscroll`, `qa:links`, `qa:states`, `qa:cls`;
- пікселі «до/після» при зміні шаблону — знімки секцій на 1200/1440/1728/1920 проти попередньої збірки.
